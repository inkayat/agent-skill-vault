# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- `catalog.yaml` is the single hand-maintained source of truth and the only authority. Nothing in this repo is generated, so there is no generator to run: after any edit, `bun test`. It has three parts: `sources` (provenance/license), `entries` (curation rows), and `vendored` (the authoritative inventory of every maintained byte under `skills/`).
- `vendored` owns each file's `source`, `upstream_path` and `sha256`. Entries carry **no** hash, and no test hardcodes a commit (`tests/provenance.test.ts` fails on a second copy of a pin). A pin bump walks the inventory rows for that source; the README's "Pin bump procedure" is the full recipe. Vendor upstream files at their real relative paths — a wrong local path breaks both a body's own `../_shared/...` pointers and the inventory's pin check.
- Content model: `firstmate-config` pins/caches this repo's own root, not any upstream repo. Every `firstmate_candidate` AND `reference-only` entry has a real local `vault_path` that must also be a `vendored` row (`skills/upstream/<source>/...` untouched, or `skills/adapted/...` rewritten); `installed`/`catalog`/`team-only`/`restricted` never carry one. `reference-only` resolves by exact id/Captain reference only, never by category/auto selection (`lookupByCategory` filters to `firstmate_candidate` + `auto-candidate` only). See `README.md`'s "Content model" section.
- Full vocabulary, boundary rules (never globally registered, `auto-candidate` != automatic loading, project-local precedence and the final selection cap are a `firstmate-config` policy decision made outside this repo), lookup usage, the post-merge hardening decisions, and the "considered, not adopted" rationale are in `README.md` — read that before adding or changing entries, not just this file.
- Schema, validation, and render/lookup logic live in `bin/lib/catalog.ts` (single implementation shared by `bin/lookup.ts` and every test). `bin/lookup.ts --category` returns the full shortlist, never truncated, at the unchanged 8-column shape (`renderRow`). `bin/lookup.ts --id` additionally appends the row's `notes` as a 9th, final, backslash-escaped field (`renderIdRow`/`escapeTsvField`) — the caveat is always in that column now, never something a caller re-derives by grepping `catalog.yaml` (`notes` is each entry's last key, easy to miss with a short window).
- Classification is a curation act, not a regex result. Before making a body selectable (`firstmate_candidate`), read it and its recursive local references: a skill whose *process* is subagent fan-out, unmanaged worktrees, or an external model CLI belongs in `restricted`/`reference-only`, and one whose dependency tree is not worth maintaining gets demoted or removed. `tests/selectable-safety.test.ts` pins the entries already audited that way; it is not a general guarantee.
- `bun test` runs the full suite (`tests/`); `tests/local-integrity.test.ts` hash-verifies every inventory row (hard-fail, no skip) and, network-optionally, confirms it's still byte-identical to the live pinned commit — a reachable non-200 there is a failure, not a skip. `tests/dependency-closure.test.ts` proves every intra-source path reference in a vendored body resolves to another inventory row (its header states the one recorded exception and the check's honest scope).
- Rewritten derivatives belong only under `skills/adapted/` with an explicit `Source:`/`Modifications:` header (see `skills/adapted/README.md`) — never mixed into a `skills/upstream/` path, which is byte-identical to its pin by contract. When upstream behavior must change (project writes, interactive loops), adapt into `skills/adapted/`; never edit the snapshot.

## Maintaining this file

Keep this file for knowledge useful to almost every future agent session in this project.
Do not repeat what the codebase already shows; point to the authoritative file or command instead.
Prefer rewriting or pruning existing entries over appending new ones.
When updating this file, preserve this bar for all agents and keep entries concise.
