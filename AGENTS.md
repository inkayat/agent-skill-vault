# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- `catalog.yaml` is the single hand-maintained source of truth. `catalog.compact.tsv` and `sources.lock` are GENERATED by `bin/render.ts` — never hand-edit them. After any `catalog.yaml` edit: `bun bin/render.ts && bun test`. `bun bin/render.ts --check` fails (non-zero) on drift without writing.
- Content model: `firstmate-config` pins/caches this repo's own root, not any upstream repo. Every `firstmate_candidate` AND `reference-only` entry has a real local `vault_path` (`skills/upstream/<source>/...` untouched, or `skills/adapted/...` rewritten) plus a `content_sha256`; `installed`/`catalog`/`team-only`/`restricted` never carry one. `reference-only` resolves by exact id/Captain reference only, never by category/auto selection (`lookupByCategory` filters to `firstmate_candidate` + `auto-candidate` only). See `README.md`'s "Content model" section.
- Full vocabulary, boundary rules (never globally registered, `auto-candidate` != automatic loading, project-local precedence and the final selection cap are a `firstmate-config` policy decision made outside this repo), lookup usage, and the "considered, not adopted" rationale are in `README.md` — read that before adding or changing entries, not just this file.
- Schema, validation, and render/lookup logic live in `bin/lib/catalog.ts` (single implementation shared by `bin/render.ts`, `bin/lookup.ts`, and every test). `bin/lookup.ts --category` returns the full shortlist, never truncated, at the unchanged 8-column shape (`renderRow`). `bin/lookup.ts --id` additionally appends the row's `notes` as a 9th, final, backslash-escaped field (`renderIdRow`/`escapeTsvField`) — the caveat is always in that column now, never something a caller re-derives by grepping `catalog.yaml` (`notes` is each entry's last key, easy to miss with a short window).
- `bun test` runs the full suite (`tests/`); `tests/local-integrity.test.ts` hash-verifies every vendored file (hard-fail, no skip) and, network-optionally, confirms it's still byte-identical to the live pinned commit — a reachable non-200 there is a failure, not a skip.
- Rewritten derivatives belong only under `skills/adapted/` with an explicit `Source:`/`Modifications:` header (see `skills/adapted/README.md`) — never mixed into a `skills/upstream/` path.
- Pin bump procedure (re-vendor + re-hash, not just edit the sha) is in `README.md`.

Prefer rewriting or pruning existing entries over appending new ones.
